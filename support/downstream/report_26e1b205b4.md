# 图像增强 + 数字识别：展示和验证说明

本版针对领航者 XC7Z020/V3.9、OV5640、800×480 屏幕。目标是验证“增强之后，原本难以识别的数字能否被同一个识别器正确识别”。首版是固定区域内的单个数字，不是完整车牌识别系统。

## 建议展示的证据

| 维度 | 建议指标 | 怎么获得 | 不能混用的概念 |
|---|---|---|---|
| 下游任务 | 数字识别准确率，增强前后提升的百分点；各数字混淆情况 | 同一批带真值的样本、相同识别器，统计正确数/总数 | 模型置信分数不是准确率；连续视频重复帧不算独立样本 |
| 画质 | PSNR、SSIM；正常光及暗光原图/增强图 | 有空间对齐的参考图时计算；亮度、噪声、偏色、过曝另做观察 | 单纯变亮不是恢复细节；有损 JPEG/拍屏不适合做像素级硬件一致性判断 |
| 硬件 | LUT、FF、BRAM、DSP，时钟及实现时序余量 | Vivado 实际布线报告 | HLS 估算不是实际整板资源；时序通过不等于所有外部接口已严格时序约束 |
| 性能 | 实际帧率、端到端延迟、稳定运行时间 | 帧计数/时间戳、可见 LED 与屏幕的高速录像、连续运行记录 | 100 MHz 不是 100 帧/秒；帧计数可能重复处理同一摄像头内容，需结合实际输入确认 |
| 能耗（可选） | 整板输入功率和平均每帧能耗 | 相同电源、屏幕亮度、分辨率下测电压电流 | Vivado 估算功耗不能写成电表实测 |

最有说服力的短视频：先用正常光让 RAW/ENH 都正确，再逐渐降低照明，保持数字位置不变，同时拍到实物目标和屏幕上的两个结果。也保留数字识别失败、增强过曝的例子。展示统计结果时至少包括原图、Gamma、旧增强和新版增强四组电脑基线；板上本版同时实现原图和新版两个识别分支。

PSNR/SSIM 如使用 LOL 的少量探索性样本，需写清样本数及其曾参与模型选择的事实，不能当作独立泛化测试。极暗时传感器已丢失的信息无法靠提亮可靠恢复。

## 本工程 FPGA 与 ARM 的具体工作

| 部分 | 现有工程做什么 | 本次新增 |
|---|---|---|
| FPGA 的 PL 可编程逻辑 | 摄像头 DVP 接收、RGB565 转 RGB888、AXI 视频流、VDMA 搬运、NanoDCE8-Cal 定点卷积与增强曲线、视频时序及 RGB 屏幕输出 | 增强前后两个相同的数字 MLP、224×224 ROI 灰度与8×8平均池化、帧号与结果发布、框和文字像素叠加 |
| ARM / PS | 运行裸机 C 程序，通过 EMIO/SCCB 配置 OV5640，读取屏幕 ID，配置时钟、VDMA、显示及增强 IP | 配置识别 ROI，读取两路识别结果，只在帧号一致时更新显示标签，打印串口日志 |
| PS 侧 DDR 与互连 | 为视频帧提供存储，PL 的 VDMA 经 PS 高性能 AXI 接口访问 DDR | 沿用原路径，不用 ARM 循环复制图像 |
| 电脑 | Python 训练、测试和量化；Vitis HLS 生成识别 RTL/IP；Vivado 综合实现，Vitis 编译 ARM 程序 | 完成对比评估和候选下载包 |

因此，两种神经网络计算（增强和识别）都在 PL 执行，ARM 负责初始化与控制。HLS 是生成硬件的工具，板上不运行 Python，也不需要电脑替板卡识别。不要把复用厂商例程、开源增强模型和新增小组代码都写成从零原创。

当前处理链：OV5640 → DVP/颜色转换 → VDMA/DDR → RGB 通道桥 → 原图数字识别器 → NanoDCE8-Cal → 增强图数字识别器/叠加显示 → RGB 通道桥 → LCD。

## 新增模型是什么

识别模型是实际训练的全连接神经网络：28×28 灰度输入 → 32 个 ReLU 隐藏单元 → 11 类输出，25,483 个参数。类别为 0–9 和 blank（10）。blank 仅针对训练覆盖的空背景，不能拒绝所有未知物体。

训练使用 MNIST 55,000 张训练样本、18,000 张生成印刷数字和4,000张背景；另用验证集选模型。量化使用 Q12 权重、Q20 偏置、Q8 隐藏值及40位累加。MNIST 10,000 张独立测试样本的定点准确率95.46%，120张未见字体测试样本90.83%。这些均为电脑离线识别结果，不是摄像头实测。

增强仍是已经上板的 NanoDCE8-Cal：161 参数，三个深度可分离卷积块，最后一点卷积参数乘0.5、增强曲线迭代8次。该增强版本采用的是先前校准初始化，没有取得成功的蒸馏训练改进；本次新增并训练的是数字识别模型。

原图和增强分支使用同一份识别权重。ROI 为 x=480、y=112、224×224，位于右侧增强区域。两个识别器读取同一物理位置的增强前/后像素，先提取 ROI 再叠加框和标签。ARM 用原子“帧号+类别”寄存器匹配相同帧。顶部的 RAW 和 ENH 都指这个框里的目标；屏幕左右仍是同一画面的不同半边，不能把左半边当作右半边的原始副本。

显示标签使用已完成帧的结果，可能滞后一帧或更多；不是当前扫描像素的即时结果。移动目标时应等待画面和标签稳定。

## 如何做实物验证

1. 回来后先确认要用 JTAG 候选版本。板卡断电时设置 BOOT_CFG 两位 ON/ON，接好摄像头、屏幕和下载器，再上电。下载命令见候选包 README；本次准备过程没有执行该命令，也没有改 SD 卡。
2. 把 `demo_targets` 中某一个 `digit_0.png` 至 `digit_9.png` 在手机/电脑上全屏显示，或打印黑底白字。只显示一个数字，不要把文件管理器缩略图、中文说明或一整行数字放进 ROI。
3. 调整距离和朝向，使数字及四周黑色留白完整落入绿色框，接近正视、居中、对焦清楚，先在正常光下逐个测 0–9。识别器没有自动检测、旋转校正和目标跟踪。
4. 快速功能检查可降低手机屏幕亮度，但这是发光目标测试，可能受 PWM、反射和相机自动曝光影响；不能把亮度滑块百分比写成照度。
5. 正式暗光测试优先用固定的实体数字卡和可调照明。先固定摄像头、目标、距离、对焦及曝光/增益，再变化照明。当前启动程序沿用厂商自动曝光设置，尚未添加锁曝光测试入口；在锁定前，应说明自动曝光的影响。固定白平衡也有助于比较颜色。
6. 每个亮度建议每类数字独立放置2次，共20个有真值样本，预先排定顺序；同时测空框/非目标背景，记录误报。每次保持稳定后记录两路结果，不按成功与否挑片。统计以独立放置为单位，连续相同帧另外作为稳定性记录。
7. 若有照度计，记录实际照度、测量位置和方法；没有就用“正常/较暗/很暗”及可重复的灯光设置，勿凭照片猜 lux。所有方法比较使用相同输入、相同识别器、相同 ROI。不能重新训练每个分支后直接把差别归功于增强。
8. 最后连续运行至少5分钟，检查黑屏、撕裂、偏色、标签停更；精确帧率和延迟需另外测。本版仍待板上验证，不以编译成功替代实物成功。

串口 `DIGIT frame=... raw=... enhanced=...` 是识别输出记录，10表示背景；程序没有真值输入，不会自动算出真实准确率。配套 CSV 用于人工填写真值与结果。top-2 logit margin 是分类分数差，不是概率。

## 下一步扩展

单数字验证通过后，优先支持多个固定字符框和数字串，记录整串完全正确率。完整车牌识别还需要车牌定位、透视校正、字符/序列识别以及中文省份和字母数据，部署资源和调试成本明显增加。若后续采用电脑上的车牌模型评估增强效果，应明确标成“板上增强 + 电脑识别评估”，不能称作整套车牌识别已在 FPGA 上部署。现阶段先让增强对同一识别器的帮助可重复、可统计，再决定是否扩展。

## 数据与归属

MNIST 下载路径及校验见 `mnist_manifest.json`，校验值按 [torchvision MNIST 官方实现](https://github.com/pytorch/vision/blob/main/torchvision/datasets/mnist.py) 核对。印刷数字由本机字体渲染，不在包内分发字体文件。NanoDCE 的 MIT 许可和 Zero-DCE 上游说明随包保留；摄像头、VDMA和显示基础工程来自正点原子资料。没有使用现成车牌项目的代码或权重。
